# Contributing

Contributions are welcome if they improve the visual quality, usability, or clarity of the project.

## Ways to contribute

- Improve layout, styling, or responsiveness
- Fix broken interactions or accessibility issues
- Add new project sections or visual experiments
- Clean up structure and documentation

## Before you submit

1. Keep changes focused and easy to review.
2. Match the existing visual tone and structure.
3. Test the page in a browser after changes.
4. Avoid unnecessary refactors.

## Preferred commit style

I prefer commits to be small, intentional, and easy to follow. Treat each commit like a clear step along the path of the work: one commit should do one thing well, and the message should explain what changed and why.

- Keep commits focused on a single change or issue.
- Avoid combining unrelated fixes, formatting churn, and refactors in the same commit.
- Write commit messages in imperative mood, for example: `fix: correct landing page spacing` or `docs: add contribution guidance`.
- Prefer short, descriptive messages over vague updates like `updates` or `misc changes`.
- If a change is visual, include context in the commit message or PR description.
- Use commits as the trail of the work: readable, chronological, and reviewable.

## Pull requests

- Keep commits clear and small.
- Explain what changed and why.
- Include screenshots when the change affects visuals.
- Keep the branch history tidy so the commit path is easy to understand.

## Questions

Open an issue before starting significant work if you want to discuss an idea first.
